# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Start the dev server (auto-finds an available port 8080-8089)
python server.py

# Install Python dependencies for data extraction tools
pip install -r requirements.txt

# Extract word-form training data from DOCX files using Qwen API
python tools/extract_transform_data_with_qwen.py

# Build unit data JS files from DOCX source
python tools/build_grade8_down_from_docx.py
```

No build step — this is a vanilla JS app served as static files. Open `http://127.0.0.1:8080` after starting the server.

## Architecture

**Two-phase initialization**: `js/main.js` loads first (sets up `window.EnglishReview` global with debug helpers), dynamically imports `js/app.js`, then creates `EnglishReviewApp`. The app class (`js/app.js`) is the central orchestrator — all page navigation, answer grading, and session state live there.

**Data loading**: Unit data lives in `data/{年级}/{学期}/{unit}.js` files (e.g., `data/八年级/Down/U1-reading.js`). Each exports a `unitData` object with `vocabulary` and `wordForms` arrays. `DataManager` fetches these as text, evaluates them with `new Function()` (to support both CommonJS and UMD export patterns), and converts them to the internal question format `{chinese, english[]}`. The server's `/api/scan-units` endpoint discovers available units by scanning the filesystem.

**Two study modes** (controlled by `this.studyMode` in app.js):
- **Normal**: Uses vocabulary entries from `.js` unit files. Questions are Chinese→English translation.
- **Transform (word-form training)**: Loads from `data/{年级}/{学期}/transform/{unit}.json` files. Questions ask for a specific word form (e.g., "able → noun form"). These JSON files are generated by `tools/extract_transform_data_with_qwen.py`, which sends DOCX content to the Qwen API.

**Grading pipeline** (`app.js:submitAnswer()`): Traditional exact-match first → if fails and AI grading enabled → call SiliconFlow API. The traditional grader normalizes by lowercasing, stripping punctuation, collapsing whitespace, and removing trailing `s` (to ignore plural differences). The AI grader uses a detailed prompt that allows 8 specific difference types (case, singular/plural, tense, verb forms, inversion, articles, possessives, synonyms) but rejects spelling errors.

**Account system**: `AccountStorage` (`js/modules/account-storage.js`) manages multi-user profiles. On first load, a modal asks for a username. User data (settings, stats, progress) is synced to `local_accounts/{user}.json` on the server via `/api/account-data` endpoints. The `beforeunload` event and `settingsChanged` custom event trigger server saves.

**Progress persistence**: Each unit's progress is saved independently in `localStorage` under `english_review_all_progress`, keyed by `{grade}-{unit}::{mode}`. Sessions auto-restore when returning to a partially-completed unit. Progress older than 24 hours is still restored (the expiry check was removed). A grade 8 migration system (`migrateGrade8Progress`) moves old "8-Down" progress entries to "8-Up".

**Key localStorage keys**: `english_review_settings_v2`, `english_review_stats_v2`, `english_review_progress`, `english_review_all_progress`, `grade8_migration_completed`, `english_review_account_name`.

## Module Roles

| Module | Role |
|---|---|
| `js/app.js` | Central orchestrator — page nav, session state, answer grading, progress save/restore |
| `js/main.js` | Entry point, `window.EnglishReview` global, dynamic import of app.js |
| `js/modules/data-manager.js` | Load unit `.js` files via fetch+eval, cache them, convert to question format |
| `js/modules/ui-manager.js` | DOM manipulation for all pages (show/hide pages, render questions, stats, notebook) |
| `js/modules/ai-grader.js` | SiliconFlow chat completions API for AI-powered answer grading |
| `js/modules/settings-manager.js` | Settings CRUD in localStorage, theme application, integrity checks |
| `js/modules/stats-manager.js` | Learning statistics, error notebook (wrong answers), achievements, export |
| `js/modules/account-storage.js` | Multi-user profiles with server-side JSON persistence |

Remaining modules (`audio.js`, `background.js`, `error-manager.js`, `file-handler.js`, `message.js`, `pomodoro.js`, `ui.js`, `data.js`) appear to be from a previous architecture and import from non-existent paths (`../config/constants.js`, `../utils/storage.js`). They are not imported by the current app.

## Data File Format

```js
// data/{年级}/{学期}/{unit}.js — uses dual export for both CommonJS and global
const unitData = {
  "title": "八年级下册 Unit 1 Reading(1)",
  "vocabulary": [
    { "english": ["answer1", "alternative"], "chinese": "中文含义" }
  ],
  "wordForms": [
    { "word": "able", "forms": [
      { "type": "adjective", "chinese": "能够的", "form": "able" },
      { "type": "noun", "chinese": "能力", "form": "ability" }
    ]}
  ]
};
// Dual export pattern at bottom of file:
if (typeof module !== 'undefined' && module.exports) { module.exports = { unitData }; }
if (typeof window !== 'undefined') { window.unitData = unitData; }
```

The `transform/` JSON files have a different schema: `{ "transformQuestions": [{ "source", "target", "target_pos", "target_meaning", "prompt_zh" }] }`.

## CSS Architecture

`style.css` is a single large file using CSS custom properties for theming (dark glassmorphism). Variables defined in `:root`: `--glass-bg`, `--glass-border`, `--accent-blue: #00f2ff`, `--accent-purple: #bd00ff`, etc. The design uses a dark background with glow orbs, grid overlay, and glass-morphism cards. Fonts: Inter (body), Oswald (display).
